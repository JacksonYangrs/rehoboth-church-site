# 网站与每日灵修拆分 — 设计文档

> 目标：把当前「整站 = 每日灵修」改造为「利河伯教会网站 + 每日灵修作为其中一个栏目」。
> 范围：骨架 + 灵修栏目（首页 + 全站导航/页脚 + `/灵修` 栏目落地，其余栏目用「筹备中」占位页）。
> 部署：静态导出 + GitHub Pages 子路径，现有 `basePath` / CI 机制保持不变。

---

## 1. 信息架构与路由

采用 vinext（Next.js App Router）文件路由 + 静态导出（`output: "export"`、`trailingSlash: true`）。每个一级栏目是一个独立可访问的页面，便于书签与分享。

```
app/
  layout.tsx            # 根布局：<html><body> + 全局导航 + {children} + 页脚 + metadata(metadataBase)
  globals.css           # 现有灵修 token + 新增 .site-* 教会外壳样式
  nav.ts                # 导航数据单一来源（NAV_ITEMS）
  components/
    SiteHeader.tsx      # 顶部导航（server component，纯 <a> 链接）
    SiteFooter.tsx      # 页脚（server component）
    PlaceholderPage.tsx # 「筹备中」占位页（server component，props: title / description）
  page.tsx              # 【新建】教会首页（server component，导出 metadata）
  灵修/
    layout.tsx          # 【新建】栏目级布局：导出栏目 metadata + 面包屑子头部
    page.tsx            # 【搬入】灵修阅读器（原 app/page.tsx 整体移入，"use client"）
  线上敬拜/page.tsx      # 占位页 → <PlaceholderPage title="线上敬拜" />
  教会成长/page.tsx      # 占位页
  查经公告/page.tsx      # 占位页
  建堂专题/page.tsx      # 占位页
  奉献/page.tsx          # 占位页
  爱心窗口/page.tsx      # 占位页
  认识教会/page.tsx      # 占位页
```

| 路径 | 页面 | 类型 | 内容 |
|---|---|---|---|
| `/` | 教会首页 | server component | 教会介绍 + 各栏目入口 + 灵修栏目 CTA |
| `/灵修` | 每日灵修 | client component | 现有灵修功能 100% 保留 |
| 其余 7 个 | 筹备中 | server component | 统一占位页 |

## 2. 导航数据与全站外壳

**单一来源** `app/nav.ts`：

```ts
export const NAV_ITEMS = [
  { label: "首页", href: "/" },
  { label: "每日灵修", href: "/灵修" },
  { label: "线上敬拜", href: "/线上敬拜" },
  { label: "教会成长", href: "/教会成长" },
  { label: "查经公告", href: "/查经公告" },
  { label: "建堂专题", href: "/建堂专题" },
  { label: "奉献", href: "/奉献" },
  { label: "爱心窗口", href: "/爱心窗口" },
  { label: "认识教会", href: "/认识教会" },
];
```

**关键决策（子路径兼容）**：顶部导航使用**普通 `<a>` 而非 Next `<Link>`**。
原因：本项目刻意不在 `next.config.ts` 设 `basePath`（vinext 0.0.50 设了会导致预渲染探测 `/` 失败、首页不生成 `index.html`）。因此 Next router 不知道子路径前缀；若用 `<Link>`，客户端跳转会落到根路径 `/灵修` 而 404。改用普通 `<a>` 后，构建后脚本 `apply-base-path.mjs` 会把 `href="/灵修"` 改写为 `href="/rehoboth-church-site/灵修"`，浏览器做整页加载，在 GitHub Pages 上正确命中 `灵修/index.html`。对内容型教会网站，整页跳转完全可接受，且彻底规避 router basePath 问题。

`SiteHeader` / `SiteFooter` 为 server component（无交互），由根 `layout.tsx` 包裹所有页面，因此灵修栏目也自带全站导航与页脚。

## 3. 灵修栏目（搬入，功能不变）

- 把当前 `app/page.tsx`（437 行，含 `Home` 组件、`getSchedule`、`STEPS`、localStorage 进度等）**整体移动**到 `app/灵修/page.tsx`，仅改组件名为 `DevotionPage`，逻辑、数据获取、样式类名不动。
- 数据获取维持现状：`fetch(\`${ASSET_PREFIX}/devotion/week-${week}.json\`)`,其中 `ASSET_PREFIX = process.env.NEXT_PUBLIC_BASE_PATH ?? ""`（构建期注入）。
- **移除**灵修页内部的 `.site-header`（原「每日与主同行」字标条），避免与全站导航重复；保留 `.today-intro` 作为栏目 Hero。
- 灵修页内部字标如有保留需求，链接指向 `/`（教会首页）而非 `#today`。
- 灵修页是 `"use client"` 组件，无法导出 `metadata` → 由新建的 `app/灵修/layout.tsx`（server component）导出栏目 metadata（标题「每日与主同行」、OG 等）。

## 4. 视觉与样式方案

复用 `app/globals.css` 现有 token，新增教会外壳专用类，避免与灵修主题冲突：

- **教会外壳（导航/页脚/首页/占位页）**：采用设计文档主色——深夜蓝（幽暗、安静）、暖白、柔金、米灰、少量水蓝。类名前缀 `.site-`（如 `.site-header`、`.site-footer`、`.site-hero`）。
- **灵修栏目**：保留现有森林绿 / 鼠尾草 / 金 / 纸色 token（`.devotion-*`、`.today-intro` 绿渐变等），作为「特别栏目」的专属视觉签名。
- 两者并存是有意的：全站统一在深夜蓝调性下，灵修栏目用绿色点缀，凸显其「每日同行」的安宁气质。

首页拟复用 `public/` 现有素材：`church-hero.png`（Hero）、`church-logo.jpeg`（Logo）、`worship-documentary.png` / `bible-study-film.png`（栏目图）、`window.svg` / `globe.svg`（图标）。

移动端导航：用 CSS-only 折叠菜单（checkbox 技巧），使首页保持 server component、零客户端 JS。

## 5. 首页内容规划（草案）

1. **Hero**：教会 Logo + 标语「在这里敬拜，在这里同行，在这里见证神的信实」+ 主日敬拜入口。
2. **灵修栏目 CTA 卡片**：醒目位置放「每日与主同行」入口，链接 `/灵修`——落实「灵修作为网站一个特别栏目」。
3. **栏目网格**：线上敬拜 / 教会成长 / 查经公告 / 建堂专题 / 奉献 / 爱心窗口 / 认识教会，每项一张卡，链接到对应占位页。
4. **聚会时间与联系方式** + 页脚。

## 9. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 中文路径目录名（如 `灵修/`）在个别工具链下编码异常 | GitHub Pages 原生支持 UTF-8 路径；`apply-base-path.mjs` 已覆盖中文 `href`；本地用 `python -m http.server` 子路径验证。若仍不行，回退为 ASCII slug（`/devotion`）但导航显示中文「每日灵修」。 |
| 多页整页跳转体验 | 内容型站点可接受；后续如需 SPA 化再评估设 `basePath` 可行性。 |
| 灵修页移除内部 `.site-header` 后导航缺失 | 全站 `SiteHeader` 已提供 Logo（→首页）与栏目链接，覆盖该需求。 |
